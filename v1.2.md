## ⭐ The rules ALL of this follows (the Trust Constitution)
_For a money app, one wrong or doubled number destroys trust for good — and trust is the moat. So these
are the spec, not polish. Full detail: memory `trust-constitution-capture-laws`._
1. **Two-Second Rule** — any money event enters in ≤2s, zero typing, zero deciding. If a flow can't hit that, it doesn't ship.
2. **Never confidently wrong** — log only when sure; when unsure, ASK. Train Echo on real MY payment screenshots BEFORE any silent capture.
3. **Always tell the user** — every auto-log fires a notification/card, with one-tap undo.
4. **Never double-count** — dedup across screenshot + notification + share + manual. One payment, one entry.
5. **Prove it's right** — monthly statement import reconciles + stamps the month "verified ✓".

## 1) Capture — "the money app you never have to type into"
_The shine layer. Make logging effortless on BOTH platforms. Reuses the on-device ML Kit reader +
`logTextFromShare` + the `ShareStore.kt` native-bridge pattern you already have._

- [ ] 🔴 **Screenshot sweep (iPhone + Android).** Malaysians already screenshot payments. On app-open, scan NEW screenshots (on-device), run the existing parser, show "I caught 4 payments — tap to confirm." **Reader half already exists** (`recognizeRows`→`parsePaymentScreenshot`→`logPaymentFromShare`); on-device = free + private; Duitful doesn't do it.
  - Needs: add **`expo-media-library`** (to read the Screenshots album) → **native rebuild** (not OTA). Photo-permission string already present.
  - Catches: photo permission is sensitive (opt-in, clear copy, works if they say no); iOS "limited photo access" mode breaks silent scan (ask full access w/ reason or degrade); only scan NEW since last time, small batches; parser already drops non-payments. → memory `local-soul-borrowed-behaviors`, `trust-constitution-capture-laws`
- [ ] 🔴 **Android notification capture.** Silently read bank/e-wallet payment notifications → auto-log. **Play ALLOWS it** (not restricted like SMS; Duitful/BudgetBakers precedent). Reuses ~70% (`logTextFromShare` + `ShareStore.kt` → a new `NotificationListenerService`).
  - Android-ONLY (iOS forbids it forever). ~55–75% coverage by value, **0% cash**. Needs `BIND_NOTIFICATION_LISTENER_SERVICE` (user enables in Settings). Main risk: **OEM battery-killers** (Xiaomi/Oppo/Vivo/Realme/Huawei) silently kill the listener → foreground service + rebind + whitelist education. CIMB only pushes ≥RM1,000 by default. → memory `android-notification-capture-feasibility`
- [ ] 🔴 **WhatsApp-number capture (the headline out-of-box idea).** Potraces becomes a WhatsApp Business contact — forward a payment screenshot or a Manglish **voice note** → parser logs it → "Dah catat ✓ RM12, nasi lemak." **Any phone, ZERO app rebuild (server-side), spreads install-free through family groups.**
  - Catches: server OCR costs per image (cap free tier); Meta Business API approval + **verify current pricing**; platform dependency → it's the funnel MOUTH, never the home (ledger stays in-app). Could even be prototyped server-side without touching the app build. → memory `local-soul-borrowed-behaviors`
- [ ] 🔴 **Dedup-by-UI (solves the hardest problem simply).** Screenshot + notification + manual = same RM12, no shared ID. Don't build a fancy matcher first — the daily review card **groups near-twins visually (same amount ± time window); one tap merges.** Every merge = labeled training data that teaches the future auto-dedup.

## 2) Pricing + streak (ROUGH numbers, streak mechanic AGREED)
_Full detail: memory `pricing-streak-plan`. Changing prices → **docx-sync rule fires.**_

- [ ] 🟡 **Decide final prices.** Rough: **Basic RM3.99 · Pro RM9.99 · Premium RM20.**
  - **Premium must = the SELLER/BUSINESS tier** (RM20 is Netflix-money for a consumer budget app; sellers bear RM19–29 because it's livelihood — anchor on seller reports / tax pack / Buku 555 / multi-staff).
  - **Basic is earnable free via streak → it's a ~RM0 engagement tier; real revenue = Pro + Premium.**
- [ ] 🔴 **The streak — "close your day" (NOT "just open the app").** Earn/keep **Basic** by closing your day **14 days straight each month.** A day counts when the user does ONE of:
  - **logs/confirms ≥1 spend** (ANY method — auto-capture counts), OR
  - taps **"No-spend day ✓"** (celebrated as a badge — fair to savers, covers cash days, removes fake-RM0.01 gaming). Frame = *tutup buku*.
  - **Add a streak-freeze** (forgive 1–2 missed days/month) so a real miss (sick, no signal) doesn't nuke the earned plan. Lives in **Pulse**.
- [ ] 🟡 **Settle the earn-matrix** across the 3 tiers: streak→Basic, share→Pro (existing "Share & Earn Pro"), referral→?, redeem→?. Rule: every earn-mechanic should reward a behaviour that also builds the moat (streak→daily data, share→distribution, referral→network). Keep it simple.

## 4) AI Assistant Interoperability (MCP — "works with ChatGPT · Claude · Gemini · Kimi")
_Reach, not core. **Gated** — see the two gates. Detail: memory `ai-agent-era-positioning`._

**The core distinction (don't blur):** the AI working *inside* Potraces (that's Echo — CORE, near-term, NOT here)
vs Potraces being *reachable from* the assistants (THIS — a reach/distribution play, a doorway not a home).

**Two gates — both must be TRUE before building:**
1. There's a **ledger worth querying** (enough captured history).
2. **Assistant usage in Malaysia has grown** (today almost no one does finance in ChatGPT here).

**Locked design principles:** read-only tools first; explicit opt-in + scoped OAuth, revocable, never default-on; **billing stays in Potraces** (no assistant has an in-app subscription rail); privacy caveat (piping the ledger to OpenAI/Google weakens the "we don't sell your data" moat — consented, minimal, disclosed); **be reachable, stay owned.**

- [ ] 🔴 One **MCP server** wrapping the existing Supabase query API (no app rewrite).
- [ ] 🟢 Read-only tools: `get_spending_summary`, `list_transactions`, `get_budget_status`, (seller) `get_profit_summary`.
- [ ] 🔴 OAuth 2.1, scoped read-only.
- [ ] 🟢 In-app consent screen ("Connect to ChatGPT/Claude — read-only, revocable").
- [ ] 🟡 Data-safety / privacy-policy update.
- [ ] 🚫 NOT in v1.2: any write/move-money tool; making the assistant the home; moving billing off-app; improving Echo (that's core, tracked with Echo work).
